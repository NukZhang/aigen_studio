# 第五阶段执行计划：UI原型生成与代码一致性保障

## 执行日期
2026-02-05

## 目标
在现有对话流中引入 UI 原型生成环节，实现"先看UI再生成代码"的交互模式，确保生成的代码与 UI 设计保持一致，提升用户体验和代码质量。

## 核心功能

### 1. UI 原型生成阶段
- **功能描述**：在需求理解确认后，先生成 UI 原型（HTML页面），供用户预览和确认
- **数据来源**：AI 根据需求理解生成静态 HTML UI 原型
- **存储位置**：`generated-code/job-{id}/ui-prototype/` 目录
- **输出文件**：
  - `index.html` - 主页面
  - `assets/` - 相关资源（图片、CSS等）

### 2. UI 原型确认流程
- **功能描述**：用户预览 UI 原型后确认，或提出修改意见
- **交互方式**：
  - 弱化"确认理解"按钮（缩小样式，降低视觉权重）
  - 新增"确认 UI 设计"按钮
  - 支持在对话中继续提出修改意见

### 3. UI 原型预览 Tab
- **功能描述**：右侧面板新增"UI原型"Tab，展示生成的 HTML 原型
- **实现方式**：
  - 使用 iframe 嵌入 HTML 原型
  - 采用 iPhone 15 Pro 手机边框样式（参考现有预览界面）
  - 支持实时预览

### 4. 代码生成时参考 UI HTML
- **功能描述**：生成代码时，将已确认的 UI HTML 作为上下文输入
- **实现方式**：
  - 将 UI HTML 文件内容读取并传递给 AI
  - 在提示词中明确要求生成的代码与 UI 保持一致
  - 确保前端页面结构与 UI HTML 对应

### 5. 对话阶段扩展
- **新增阶段**：
  - `UI_GENERATING` - UI 生成中
  - `UI_CONFIRMED` - UI 已确认，准备生成代码

## 技术架构

### 前端技术栈
- Vue 3 + TypeScript + Element Plus
- Monaco Editor（代码编辑器）
- iframe（HTML 预览）
- iPhone 15 Pro 样式框架

### 后端技术栈
- Spring Boot 3.2 + JPA
- iFlow SDK（AI 代码生成）
- 文件系统操作（读取/保存 HTML）

### 工具依赖
- `pencil-ui-design` Skill - 工业级 UI 设计工作流（必选，用于提升 UI 质量）
- `frontend-design` Skill - 高质量前端界面设计（必选）

## 执行流程

```
需求输入
  ↓
理解需求（AI 理解并生成 IR）
  ↓
确认理解（弱化状态栏，点击确认按钮进行下一步）
  ↓
生成 UI HTML（AI 根据需求生成静态 HTML 原型）
  ↓
预览 UI 原型（UI原型 Tab 中展示）
  ↓
确认 UI 设计（用户确认或提出修改）
  ↓
生成代码（参考 UI HTML 生成前后端代码）
  ↓
确认启动（启动预览服务）
  ↓
预览最终应用
```
